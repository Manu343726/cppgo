**Audience:** you are reading generated code to debug a call, or deciding what
to commit.

## The file set

One `cppgo gen` run writes five things:

| path | contents |
|---|---|
| `zz_cppgo.gen.go` | the API, `Open`, the resolver, one wrapper per binding, the trampoline declarations |
| `zz_cppgo_amd64.s` | one `NOSPLIT` trampoline per binding, plus `cppgo_free` when a result is copied out |
| `cppgo_shim/zz_cppgo_shim.h` | the `extern "C"` thunk declarations |
| `cppgo_shim/zz_cppgo_shim.cpp` | the thunks, the thread-local error message, `cppgo_last_error` |
| `libcppgo_<package>.so` | the shim, compiled and linked against your library |

The first four are sources you commit. The fifth is a build artefact: `cppgo
gen` compiles it, `cppgo check` does not compare it.

The shim's sources live in a subdirectory because the Go tool refuses a
directory containing a `.cpp` unless the package uses cgo — and a generated
package never does.

Every generated file starts with the banner and, in the Go file, the exact
command that produced it:

```go
// Code generated by cppgo gen. DO NOT EDIT.
//
//	cppgo gen -header include/analytic/analytic.hpp -package analytic -library build/libanalytic.so -out ./analytic
```

Edit the C++ header, never the generated files. `cppgo check` exists to catch
exactly that.

## `zz_cppgo.gen.go`

### `Open` and the two objects

```go
// Open loads the cppgo-built shim and, when the package has one, the user's
// library it was linked against, then resolves every symbol this package binds.
func Open(path string) error { return cppgoOpen(path) }

// CppgoLibraryPath overrides where the user's library is loaded from, for a
// deployment that does not keep it beside the shim.
var CppgoLibraryPath string

const (
	cppgoShimName    = "libcppgo_analytic.so"
	cppgoUserLibrary = "libanalytic.so"
	cppgoLibraryPathEnv = "CPPGO_LIBRARY_PATH"
)
```

The shim names the user's library by **soname**, never by the build path. The
generated loader looks for it at `CPPGO_LIBRARY_PATH`, then `CppgoLibraryPath`,
then beside the shim, then on the loader's search path, and opens the shim
after it. `Open("")` uses `cppgoShimName`.

### One address per symbol

Each binding gets a `uintptr`, named after the symbol or the thunk:

```go
var (
	cppgoSym_af56435cc9d1 uintptr // cppgo_thunk_af56435cc9d1
	cppgoSym_eafad677153b uintptr // _ZNK8analytic6Signal6scaledEd
	cppgoFreeSym          uintptr // cppgo_free
)
```

Resolution happens once per process, under a mutex. A thunk that cannot be
resolved means the `.so` beside the package is not the one the generated Go was
built against, and the message says so: *the shim cppgo compiled is stale; run
cppgo gen again*.

### The types

A record whose fields are all public and whose layout matches Go is **mirrored**,
with a compile-time assertion of every size, alignment and offset:

```go
type Point struct {
	X float64
	Y float64
}

var _ [16]byte = [unsafe.Sizeof(Point{})]byte{}
var _ [8]byte = [unsafe.Alignof(Point{})]byte{}
var _ [0]byte = [unsafe.Offsetof(Point{}.X)]byte{}
var _ [8]byte = [unsafe.Offsetof(Point{}.Y)]byte{}
```

Everything else is opaque and holds a `*cppgo.Object`:

```go
type Signal struct {
	obj *cppgo.Object
}
```

The layout of a mirrored record is measured from libclang, not guessed. A record
with private members, a union, a reference, a bitfield or a non-mirrorable field
takes the opaque path, and its public fields get generated accessors.

### The wrapper shapes

Every wrapper follows the same five steps: open/probe, convert the arguments,
call the trampoline, keep the arguments alive, convert the result. What differs
is the carrier.

**Direct** (`noexcept`, out of line, register class): no status, no error.

```go
func (s *Signal) Scaled(k float64) float64 {
	if s == nil || s.obj == nil {
		panic("cppgo: analytic::Signal::scaled(double) const noexcept on a closed Signal")
	}
	if err := cppgoOpen(""); err != nil {
		panic(err)
	}
	cppgo.ProbeStack()
	cppgoRet := cppgoCall_eafad677153b(cppgoSym_eafad677153b, s.cppgoAddr(), k)
	cppgo.KeepAlive(s)
	return cppgoRet
}
```

**Thunk** (not `noexcept`, virtual, inline, `std::`, by value): a status and a
value through an out-pointer.

```go
func (s *Signal) Gain() (float64, error) {
	if s == nil || s.obj == nil {
		return 0, cppgo.ErrClosed
	}
	if err := cppgoOpen(""); err != nil {
		return 0, err
	}
	cppgo.ProbeStack()
	var cppgoResult float64
	cppgoStatus := cppgoCall_f522a9b5b52d(cppgoSym_f522a9b5b52d, s.cppgoAddr(), unsafe.Pointer(&cppgoResult))
	cppgo.KeepAlive(s, &cppgoResult)
	if cppgoStatus != 0 {
		return 0, cppgoCallError("analytic::Signal::gain")
	}
	return cppgoResult, nil
}
```

**Constructor**: allocate the measured size, call the thunk with the address as
`this`, and release the storage if the constructor throws.

**`std::string` / `std::vector` result**: the shim copies the value into a heap
block, the Go side copies it into a string or a slice, and `cppgo_free` releases
the block:

```go
cppgoStatus := cppgoCall_a3b9d8f3fd66(cppgoSym_a3b9d8f3fd66,
	cppgo.StrPtr(prefix), uint64(len(prefix)), value,
	unsafe.Pointer(&cppgoData), unsafe.Pointer(&cppgoSize))
if cppgoStatus != 0 {
	return "", cppgoCallError("analytic::describe")
}
var cppgoResult string
if cppgoSize != 0 {
	cppgoResult = string(unsafe.Slice((*byte)(cppgoData), int(cppgoSize)))
}
cppgoFree(cppgoFreeSym, cppgoData)
return cppgoResult, nil
```

**Callback**: the reentrant carrier. The Go function is registered as a table
slot, the frame carries `this`, the callback address and the arguments, and the
call goes through `cppgo.CallReentrant`:

```go
cppgoCallback0, cppgoCallbackErr := cppgo.RegisterCallback(func(cppgoFrame *cppgo.Args) {
	cppgoFrame.Ret = uintptr(int64(fn(int32(cppgoFrame.I[0]))))
})
if cppgoCallbackErr != nil {
	return 0, cppgoCallbackErr
}
defer cppgo.ReleaseCallback(cppgoCallback0)
var cppgoFrame cppgo.Args
cppgoFrame.I[0] = uintptr(s.cppgoAddr())
cppgoFrame.I[1] = uintptr(cppgoCallback0)
cppgoFrame.I[2] = uintptr(int64(value))
cppgoFrame.I[3] = uintptr(unsafe.Pointer(cppgoResult))
cppgo.CallReentrant(cppgoSym_bfb59bf5bb3f, &cppgoFrame)
if cppgoPanic := cppgo.TakeCallbackPanic(); cppgoPanic != nil {
	panic(cppgoPanic.Value)
}
```

### The trampoline declarations

The Go declaration and the assembly `TEXT` must agree on the frame layout,
which `go vet`'s asmdecl checks on every build:

```go
// cppgoCall_eafad677153b is the NOSPLIT trampoline for _ZNK8analytic6Signal6scaledEd.
func cppgoCall_eafad677153b(fn uintptr, this uintptr, a1 float64) float64
```

The parameters are mirror types: `int64` for every integer width,
`unsafe.Pointer` for pointers and slice data, `float32`/`float64` for floats.

## `zz_cppgo_amd64.s`

```asm
// func cppgoCall_eafad677153b(fn uintptr, this uintptr, a1 float64) float64
TEXT ·cppgoCall_eafad677153b(SB), NOSPLIT, $0-32
	MOVQ	fn+0(FP), R12
	MOVQ	this+8(FP), DI
	MOVSD	a1+16(FP), X0
	MOVQ	SP, R13
	ANDQ	$~15, SP
	CALL	R12
	MOVQ	R13, SP
	MOVSD	X0, ret+24(FP)
	RET
```

- `$0-32` is a zero-frame function whose argument block plus result is 32 bytes;
  the `x+off(FP)` offsets are generated.
- Arguments are loaded **before** `SP` moves and the result is stored **after**
  it is restored, because `FP` is relative to `SP`.
- The `SP` switch, its 16-byte alignment and `NOSPLIT` are explained in [How it
  works]({{< ref "project/architecture.md" >}}).

The file uses Go's assembler, not GNU `as`: `·` is the package-local symbol
separator and `textflag.h` provides `NOSPLIT`.

## The shim

`cppgo_shim/zz_cppgo_shim.cpp` includes the header cppgo parsed and defines the
thunks. Every one clears the error message first, wraps its body in a `try`, and
returns a status:

```cpp
thread_local std::string cppgo_error_message;

extern "C" const char *cppgo_last_error(void) {
	return cppgo_error_message.c_str();
}

extern "C" int32_t cppgo_thunk_d691e1c0b71e(int32_t a, int32_t b, int32_t * cppgo_result) {
	cppgo_error_message.clear();
	try {
		*cppgo_result = ::analytic::ratio(a, b);
		return 0;
	} catch (const std::exception &error) {
		cppgo_error_message = error.what();
		return 1;
	} catch (...) {
		cppgo_error_message = "unknown C++ exception";
		return 1;
	}
}
```

A thunk that returns a `std::string` or a `std::vector` allocates the copy with
`::operator new[]`; the shim also defines `cppgo_free`, which is what the Go
wrapper calls after it has read the bytes. The shim is linked with
`-Wl,-rpath,$ORIGIN`, so it finds the user's library beside it.

The shim is **cppgo's code, not yours**. It is generated from the same parse as
the Go API, and the header comment in `zz_cppgo_shim.h` says so.

## Regenerating

```console
$ cppgo gen -header include/analytic/analytic.hpp -package analytic \
      -library build/libanalytic.so -out ./analytic
$ cppgo check -header include/analytic/analytic.hpp -package analytic \
      -library build/libanalytic.so -out ./analytic
```

`gen` writes and compiles; `check` compares. Both are deterministic — bindings
are sorted and thunk names come from a stable hash — and `gen` formats the Go
files before writing them. See [cppgo check in CI]({{< ref "manual/ci.md" >}}).
