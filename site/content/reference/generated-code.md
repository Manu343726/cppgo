## The file set

A direct-ABI run writes two new files and rewrites the input:

| file | contents |
|---|---|
| `zz_cppgo.gen.go` | idiomatic wrappers, lazy library binding, trampoline declarations |
| `zz_cppgo_amd64.s` | one `NOSPLIT` trampoline per bound function |
| your own `.go` file | rewritten in place, every bound body replaced by a delegation |

The third artifact is easy to miss: with the default `-out` (which is `-dir`),
the input file is rewritten **in place**. Only when `-out` names a different
directory does the rewritten source become a separate file, `zz_cppgo_stub.go`.
That is deliberate — regeneration is idempotent, the directives stay where you
wrote them, and the package keeps compiling.

In ABI mode there is **no `cppgo_shim.h`**. ABI mode calls the C++ symbol
directly, so there is no `extern "C"` layer and nothing for the C++ side to
implement. A leftover `cppgo_shim.h` from an earlier shim-mode run is reported
as a warning and left alone; the generator only owns the files it wrote.

Every generated file starts with the same banner:

```go
// Code generated by cppgo gen. DO NOT EDIT.
```

The generator ignores files carrying that banner when it reads its input, so a
package can be regenerated into its own source directory without reading its own
output. Edit the directives and the declarations, never the generated files:
`cppgo check` exists to catch exactly that.

## `zz_cppgo.gen.go`

### The header and the library binding

```go
package mathx

import (
	"fmt"
	"sync"
	"unsafe"

	"github.com/Manu343726/cppgo"
)

// CppgoLibraryPath overrides the shared library opened by this package's
// generated bindings. It is read once, on the first call; leave it empty to
// use the name given to the //cppgo:library directive.
var CppgoLibraryPath string

// cppgoLibraryName is the library named by //cppgo:library.
const cppgoLibraryName = "libmathx"
```

`CppgoLibraryPath` is the only knob exposed to the program: setting it before
the first call loads a different file with the same symbols. `sync` is imported
for the `sync.Once` below; `unsafe` appears only when a slice, pointer or the
object allocator needs it.

### One address per symbol

```go
var (
	cppgoOnce sync.Once
	cppgoLib  *cppgo.Library
	cppgoErr  error

	// cppgoSymDot is the resolved address of the "_ZNK5mathx6Vector3dotEPKdm" symbol.
	cppgoSymDot uintptr
	// cppgoSymNew is the resolved address of the "_ZN5mathx6VectorC1Edd" symbol.
	cppgoSymNew uintptr
	// ...
)
```

Each binding gets one `uintptr`, named `cppgoSym<GoName>`. Resolution happens
**once per process**, not per call:

```go
func cppgoEnsure() error {
	cppgoOnce.Do(func() {
		path := cppgoLibraryName
		if CppgoLibraryPath != "" {
			path = CppgoLibraryPath
		}
		lib, err := cppgo.Open(path)
		if err != nil {
			cppgoErr = fmt.Errorf("cppgo: opening %s: %w", path, err)
			return
		}
		for _, sym := range []struct {
			name string
			addr *uintptr
		}{
			{name: "_ZNK5mathx6Vector3dotEPKdm", addr: &cppgoSymDot},
			{name: "_ZN5mathx6VectorC1Edd", addr: &cppgoSymNew},
		} {
			addr, err := lib.Symbol(sym.name)
			if err != nil {
				_ = lib.Close()
				cppgoErr = fmt.Errorf("cppgo: %s: %w", path, err)
				return
			}
			*sym.addr = addr
		}
		cppgoLib = lib
	})
	return cppgoErr
}
```

The `sync.Once` is why a missing symbol surfaces on the **first call** and every
later call reports the same error. The error is wrapped twice: `cppgo: opening
<path>: cppgo: open "<path>": <loader>` for a load failure, and
`cppgo: <path>: cppgo: symbol "<mangled>": <loader>` for a resolution failure.
The library is closed on a partial resolution so the process does not keep a
half-bound handle.

### The object registry (only with a constructor)

```go
var (
	cppgoObjectsMu sync.Mutex
	cppgoObjects   = map[cppgo.Handle][]byte{}
)

func cppgoAlloc(size, align int) cppgo.Handle {
	buf := make([]byte, size+align)
	offset := 0
	if align > 1 {
		offset = (align - int(uintptr(unsafe.Pointer(&buf[0]))%uintptr(align))) % align
	}
	handle := cppgo.Handle(uintptr(unsafe.Pointer(&buf[offset])))
	cppgoObjectsMu.Lock()
	cppgoObjects[handle] = buf
	cppgoObjectsMu.Unlock()
	return handle
}

func cppgoRelease(handle cppgo.Handle) {
	cppgoObjectsMu.Lock()
	delete(cppgoObjects, handle)
	cppgoObjectsMu.Unlock()
}
```

This block is emitted only when the package binds a constructor or a destructor.
`cppgoAlloc` returns the address of a zeroed buffer aligned to `align`, and
records the **whole** buffer (not the aligned start) so the collector keeps it
alive. `size` and `align` are literals measured from the header by the
generator, not values computed at run time.

`cppgoRelease` is called by the generated destructor after `D1`. Deleting an
entry that is not there is harmless: a handle allocated elsewhere is simply not
in the map.

### The bool helper (only when used)

```go
func cppgoBoolInt64(v bool) int64 {
	if v {
		return 1
	}
	return 0
}
```

A Go `bool` crosses as an integer 0 or 1. The helper exists so the wrapper reads
as a call, not as a branch; it is emitted only when a binding has a `bool`
parameter.

### A wrapper

```go
// Dot returns the dot product with another vector's components.
//
// cppgoCallDot binds func (v Vector) Dot(ys []float64) (float64, error).
//
// Direct C++ ABI: mathx::Vector::dot, mangled _ZNK5mathx6Vector3dotEPKdm
// (abi from compile_commands.json).
//
// Assumption: the trailing error is always nil: a direct C++ call has no status
// channel (return an int32 status and declare only error to get one).
func cppgoCallDot(v Vector, ys []float64) (float64, error) {
	if err := cppgoEnsure(); err != nil {
		return 0, err
	}
	cppgo.ProbeStack()
	cppgoRet := cppgo__ZNK5mathx6Vector3dotEPKdm(cppgoSymDot, uintptr(v),
		cppgo.Ptr(ys), uintptr(len(ys)))
	cppgo.KeepAlive(ys)
	return cppgoRet, nil
}
```

The shape is always the same:

1. **ensure** the library, returning the failure if the binding has an `error`
   result and panicking if it does not;
2. **probe** the stack;
3. **call** the trampoline: symbol address first, then `this` (for a method), then
   the arguments converted to their mirror types;
4. **keep alive** every argument that points into Go memory;
5. **convert the result** back — a `bool` becomes `ret&0xff != 0`, an `int64`
   mirror becomes the declared Go width, and a float comes back directly.

A constructor's wrapper allocates first:

```go
cppgoThis := cppgoAlloc(16, 8)
cppgo__ZN5mathx6VectorC1Edd(cppgoSymNew, uintptr(cppgoThis), x, y)
return Vector(cppgoThis), nil
```

A destructor's wrapper calls `D1` and then releases the storage:

```go
cppgo__ZN5mathx6VectorD1Ev(cppgoSymDestroy, uintptr(v))
cppgoRelease(cppgo.Handle(v))
```

### The trampoline declarations

```go
// cppgo__ZNK5mathx6Vector3dotEPKdm is the NOSPLIT trampoline for the C++ symbol
// "_ZNK5mathx6Vector3dotEPKdm".
// It must not be called directly: use Dot.
//
//go:noescape
func cppgo__ZNK5mathx6Vector3dotEPKdm(fn uintptr, this uintptr, a0 unsafe.Pointer, a0_len uintptr) (ret float64)
```

The Go declaration and the assembly `TEXT` must agree on the frame layout, and
the `//go:noescape` directive tells the compiler that no argument pointer
escapes, so the caller's data does not have to be moved to the heap for the
call. The parameters are mirror types: `int64` for every integer width,
`unsafe.Pointer` for pointers and slice data, `float64`/`float32` for floats.

## `zz_cppgo_amd64.s`

```asm
// Code generated by cppgo gen. DO NOT EDIT.

#include "textflag.h"

// func cppgo__ZN5mathx6Vector3dotEPKdm(fn uintptr, this uintptr, a0 unsafe.Pointer, a0_len uintptr) (ret float64)
TEXT ·cppgo__ZNK5mathx6Vector3dotEPKdm(SB), NOSPLIT, $0-40
	MOVQ	fn+0(FP), R12
	MOVQ	this+8(FP), DI
	MOVQ	a0+16(FP), SI
	MOVQ	a0_len+24(FP), DX
	MOVQ	SP, R13
	ANDQ	$~15, SP
	CALL	R12
	MOVQ	R13, SP
	MOVSD	X0, ret+32(FP)
	RET
```

- `$0-40` is a zero-frame function whose argument block plus result is 40 bytes;
  the offsets in `x+off(FP)` come from that layout and are generated, never
  typed by hand.
- The `SP` switch, its 16-byte alignment and the store-after-restore rule are
  explained once in [How it works]({{< ref "project/architecture.md" >}}); which
  register carries each argument is in [register
  assignment]({{< ref "manual/calling-convention.md" >}}).

The file uses Go's assembler, not GNU `as`: `·` is the package-local symbol
separator and `textflag.h` provides `NOSPLIT`.

## The rewritten source

With `-out ./gen` (a directory other than `-dir`), the third file is:

```go
// Code generated by cppgo gen. DO NOT EDIT.

// Package mathx binds mathx::Vector directly, with no extern "C" layer.
package mathx

import "github.com/Manu343726/cppgo"

//cppgo:library libmathx
//cppgo:header ../../include/mathx/vector.hpp

//cppgo:class mathx::Vector
type Vector cppgo.Handle

// New constructs a Vector.
//
//cppgo:ctor
func New(x, y float64) (Vector, error) { return cppgoCallNew(x, y) }

// Norm returns the Euclidean norm.
//
//cppgo:method norm
func (v Vector) Norm() float64 { return cppgoCallNorm(v) }

//cppgo:method dot
func (v Vector) Dot(ys []float64) (float64, error) { return cppgoCallDot(v, ys) }

//cppgo:dtor
func (v Vector) Destroy() { cppgoCallDestroy(v) }
```

Everything is preserved except the bodies:

- the banner, the package clause and the imports;
- the directives, in place, so a regeneration from this file produces the same
  bytes;
- the doc comments, minus the directive lines (they are re-emitted above the
  signature);
- the parameter names. A declaration whose parameters were unnamed or `_` gets
  names in the rewrite, so the delegating body can pass them.

The rewritten body is a single tail call. That is the whole point of the
delegation: the user-visible function is unchanged, the implementation moved to
the generated wrapper, and no `panic("not implemented")` is left behind.

## Regenerating

```console
$ cppgo gen -dir ./bindings/mathx
$ cppgo check -dir ./bindings/mathx -q
```

`gen` writes; `check` compares. Both are deterministic, and the generator
gofmts the Go files before writing them. See [cppgo check in
CI]({{< ref "manual/ci.md" >}}).
