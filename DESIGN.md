# cppgo — design contract (v3)

This file is the contract for every workstream. If something is not written here, do not invent it:
ask the orchestrator. Where the tree and this file disagree during the migration it describes, this
file is right; the decisions it replaces are recorded in
[ADR-0001](docs/adr/0001-header-first-bindings.md).

## What this is

`cppgo` calls C++ from Go with **no cgo at build time** and **no `import "C"`**. A generator reads a
C++ header, proves at build time that every declaration it binds is callable, and emits a Go package
plus one `NOSPLIT` assembly trampoline per function that enters the C++ ABI directly instead of going
through the runtime's cgo path.

A binary that loads shared libraries at run time is dynamically linked by definition. The claim is
"no C toolchain, no `import "C"`, no cgo", not "a static single file".

## The two layers

The runtime and the generator are separate products with separate dependencies, and the line between
them is part of this contract.

| layer | package | owns | may depend on |
|---|---|---|---|
| **runtime** | `github.com/Manu343726/cppgo` (repository root) | dynamic loading, symbol resolution, the C++ ABI and its trampolines, stack probing, foreign-object storage, wire helpers, error types | the standard library, `internal/asm`, `internal/rtl`, `purego` |
| **generator** | `internal/gen`, `internal/cxx`, `cmd/cppgo` | parsing C++ through libclang, discovery of compilation flags, validation, emitting Go and assembly | anything, including libclang through `purego` |

The runtime **never imports `internal/cxx`, directly or transitively, and has no libclang
dependency**. libclang is generation-time only. The runtime builds and its tests run with
`CGO_ENABLED=0` on a machine with no libclang installed; the generator needs libclang and says so
with `ErrLibclangNotFound` when it is absent.

What the generated code uses from the runtime, and nothing else:

```go
func Open(path string) (*Library, error)     // purego dlopen/dlsym underneath
func (l *Library) Symbol(name string) (uintptr, error)
func (l *Library) Close() error
func (l *Library) Path() string

func ProbeStack()                            // StackReserve bytes of goroutine stack headroom
const StackReserve = 32 << 10

func NewObject(size, align uintptr) *Object // Go storage for an object whose layout Go does not know
func (o *Object) Addr() uintptr             // pinned, aligned address handed to C++
func (o *Object) Release()                  // after the destructor has run

func Ptr[T any](s []T) unsafe.Pointer       // wire helpers
func StrPtr(s string) unsafe.Pointer
func KeepAlive(...any)
func LastError(lib *Library) error

type Handle uintptr                          // low-level only; never in a generated signature
```

`Object` pins its storage with `runtime.Pinner`, so there is no package-level object registry: the
storage is reachable from the generated Go value that owns it, and it does not move while pinned.

## The generated API

The input is C++. For this header:

```cpp
namespace mathx {

struct Point { double x, y; };

class Vector {
public:
    Vector(double x, double y);
    ~Vector();
    double x() const;
    double norm() const;
    double dot(const double *ys, std::size_t n) const;
    void scale(double k);
    static int dims();
private:
    double x_, y_;
};

// y[i] = a * x[i] + y[i] for i in [0, n).
void saxpy(double a, const double *x, double *y, std::size_t n);

Point centroid(const Point *ps, std::size_t n);

} // namespace mathx
```

`cppgo gen` writes this package — this is the API, not an illustration:

```go
// Code generated by cppgo gen. DO NOT EDIT.
//
//	cppgo gen -header include/mathx/vector.hpp -package mathx -library libmathx -out ./mathx

package mathx

// Point is mathx::Point: a POD, 16 bytes, fields at offsets 0 and 8.
type Point struct {
	X float64
	Y float64
}

// Vector is mathx::Vector. The object belongs to C++; obj is where it lives.
type Vector struct {
	obj *cppgo.Object
}

// NewVector constructs a mathx::Vector.
//
// C++: mathx::Vector::Vector(double, double), _ZN5mathx6VectorC1Edd
func NewVector(x, y float64) (*Vector, error) {
	if err := Open(""); err != nil {
		return nil, err
	}
	obj := cppgo.NewObject(16, 8)
	cppgo.ProbeStack()
	callNewVector(cppgoSymNewVector, obj.Addr(), x, y)
	return &Vector{obj: obj}, nil
}

// Close destroys the object. It returns cppgo.ErrClosed when the receiver has
// no live object: a nil pointer, the zero value, or a second Close.
//
// C++: mathx::Vector::~Vector(), _ZN5mathx6VectorD1Ev
func (v *Vector) Close() error {
	if v == nil || v.obj == nil {
		return cppgo.ErrClosed
	}
	cppgo.ProbeStack()
	callDestroy(cppgoSymClose, v.obj.Addr())
	v.obj.Release()
	v.obj = nil
	return nil
}

// X returns the x component.
//
// C++: mathx::Vector::x() const, _ZNK5mathx6Vector1xEv
func (v *Vector) X() float64

// Norm returns the Euclidean norm.
//
// C++: mathx::Vector::norm() const, _ZNK5mathx6Vector4normEv
func (v *Vector) Norm() float64

// Dot returns the dot product of v with ys.
//
// C++: mathx::Vector::dot(const double *, std::size_t) const, _ZNK5mathx6Vector3dotEPKdm
func (v *Vector) Dot(ys []float64) float64

// Scale multiplies both components by k.
//
// C++: mathx::Vector::scale(double), _ZN5mathx6Vector5scaleEd
func (v *Vector) Scale(k float64)

// Dims is the static member mathx::Vector::dims.
//
// C++: mathx::Vector::dims(), _ZN5mathx6Vector4dimsEv
func Dims() int32

// Saxpy computes y[i] = a*x[i] + y[i] in place, for i in [0, len(y)).
//
// C++: mathx::saxpy(double, const double *, double *, std::size_t), _Z5saxpydPKdPdm
func Saxpy(a float64, x, y []float64)

// Centroid returns the centroid of ps.
//
// C++: mathx::centroid(const Point *, std::size_t), _Z8centroidPKN5mathx5PointEm
func Centroid(ps []Point) Point
```

Bodies are elided where they are mechanical: load guard, `ProbeStack`, one trampoline call, result
conversion. The exported shape is the contract:

- **C++ class → Go struct with methods.** The struct has one unexported field and no exported
  layout. Its zero value is invalid: a method on a nil pointer or the zero value panics with a
  message naming the method, because there is no C++ object to call. A destructor exists, so no
  finalizer is generated (a finalizer runs on an arbitrary goroutine, possibly after the library has
  been closed).
- **Constructor → `New<Type>(...) (*Type, error)`.** Constructors never panic on a load failure;
  they return it.
- **Destructor → `Close() error`.** `cppgo.ErrClosed` for a nil receiver, the zero value, or a second
  call: a double close is reported rather than freeing twice.
- **C++ struct → Go struct with matching exported fields**, at the same offsets (see *POD layout*).
- **Free function → package function.**
- **Static member function → package function.**
- **Enum → named Go integer type plus typed constants** (`type Color uint8`,
  `const ColorRed Color = 0`): never a string and never a bare integer.
- **`cppgo.Handle` appears in no exported signature.** The generated struct's field is a pointer to
  runtime storage, and pointers to bound types are ordinary Go pointers.

## Type map

Sizes are validated against libclang's `sizeof` for the translation unit; a platform where `long` is
not 64-bit is a generation error, not a silent reinterpretation.

| C++ | Go | notes |
|---|---|---|
| `bool` | `bool` | |
| `char`, `signed char` | `int8` | plain `char` is signed on the supported targets |
| `unsigned char` | `uint8` | |
| `short`, `unsigned short` | `int16`, `uint16` | |
| `int`, `unsigned int` | `int32`, `uint32` | |
| `long`, `long long`, `unsigned long`, `unsigned long long` | `int64`, `uint64` | LP64, validated |
| `int8_t`…`uint64_t` | the same width | fixed-width aliases resolve by size |
| `intptr_t`, `ptrdiff_t` | `int64` | validated |
| `size_t`, `uintptr_t` | `uint64` | the length half of a slice pair is not visible in Go |
| `float`, `double` | `float32`, `float64` | |
| `wchar_t`, `char16_t`, `char32_t` | `int32`, `uint16`, `uint32` | validated by size |
| `T *`, `T &` (parameter) | `*T` or `[]T` | see the slice and string rules below |
| `(const T *p, size_t n)` | `[]T` | one Go parameter; T scalar, enum or POD |
| `(const char *p, size_t n)` | `string` | one Go parameter; not NUL-terminated |
| enum | named integer type | underlying type from libclang |
| bound class or POD | `*T` / `T` | POD by value only when it qualifies (see *POD layout*) |
| `void` | no result | |

Rejected by type, with the fix named: `std::string`, `std::string_view`, `std::vector<T>`,
`std::span<T>`, any other `std::` type; `long double` and `__int128` (not one eightbyte);
function pointers, `std::function`, member pointers and callbacks from C++ into Go; variadic
functions; templates that are not explicitly instantiated. A bare `const char *` that is not paired
with a length is rejected too: the contract refuses to guess whether it is NUL-terminated.

`string` and `[]T` are **parameter** forms. A C++ function cannot return one: it writes into a
caller-provided slice, or returns a POD or a pointer. That is a deliberate limitation, not a gap.

## Naming and overloads

- A name is CamelCase, split on `_`, leading and trailing underscores stripped: `count_above` →
  `CountAbove`, `x_` → `X`, `saxpy` → `Saxpy`.
- A class or struct is its own name; a namespace contributes nothing. Two declarations from different
  namespaces that map to one Go identifier are a build error naming both: generate a package per
  namespace instead of renaming.
- `New<Type>` for a constructor, `Close` for the destructor.
- A name with **one** declaration keeps its bare CamelCase form. A name with **several** overloads
  takes a suffix built from its Go parameter types, in order: `dot()` → `Dot`,
  `dot(const double *, size_t)` → `DotFloat64Slice`, `dot(Vector const &)` → `DotVector`. The
  zero-parameter overload keeps the bare name. Two overloads that still produce one Go name (their
  Go parameter types being equal) are a build error naming both.
- `Open` and `Close` are reserved by the generated package; a C++ declaration that maps to either is
  a build error naming it and the class or function that owns the name.

## POD layout

A record is a **POD** for cppgo when it has no virtual functions, no virtual or non-public base
class, no user-declared or deleted copy/move operation or destructor, and every field is public. It
is then standard-layout and trivially copyable, and its Go mirror is the same fields in declaration
order.

- Scalars, enums, fixed-size arrays of them, and nested PODs are what a POD field may be. Bitfields,
  anonymous members, references, pointers, `union` members and non-POD members are a build error
  naming the field.
- The generator reads `sizeof`, `alignof` and every field offset from libclang raw, then checks that
  Go's natural layout for the mirror produces the same numbers. A mismatch — `#pragma pack`,
  `__attribute__((packed))`, an alignment attribute Go cannot reproduce — is a build error naming
  the field, its two offsets and the fix.
- The generated file also carries a **compile-time assertion** of the size, alignment and every
  field offset. A header edited without regenerating fails `go build`, never a call.
- By value, a POD crosses only when it is at most 16 bytes and each of its eightbytes classifies as
  INTEGER or SSE. A larger or MEMORY-class aggregate is a build error with the fix "pass it as `*T`"
  (parameter) or "return it through an output argument" (result). By value is symmetric: a POD
  parameter and a POD result are both supported under that rule.
- A record with a non-public field is not mirrored: it is opaque, constructible through a
  constructor, and passes only as `*T`.

## What the generator refuses, and the message

The generator validates **the set it was asked to bind** and writes nothing unless every binding is
valid. A failure is one line per rejected binding, all reported in one run, exit code 1:

```
cppgo: <file>:<line>: <qualified C++ name>: <what is wrong>; <the fix>
```

| declaration | message |
|---|---|
| defined in its class body | `cppgo: include/mathx/vector.hpp:31: mathx::Vector::norm_squared: defined inside its class body, so the library exports no symbol; move the definition into a .cpp file` |
| virtual | `cppgo: include/mathx/shape.hpp:12: mathx::Shape::area: virtual, so the address is only known through the vtable at run time; make the function non-virtual, or bind a non-virtual wrapper that calls it` |
| template | `cppgo: include/mathx/util.hpp:8: mathx::max: a template, so it has no symbol until instantiated; add an explicit instantiation in a .cpp file and bind that` |
| `std::` type | `cppgo: include/mathx/util.hpp:22: mathx::dump: parameter 1 is std::string; take (const char *, std::size_t) instead` |
| non-POD by value | `cppgo: include/mathx/poly.hpp:18: mathx::Poly::Poly(const Poly &): a user-declared copy constructor makes the class non-trivial for calls, so it cannot cross by value; pass *Poly instead` |
| layout mismatch | `cppgo: include/mathx/packed.hpp:9: mathx::Packed: field tag is at offset 4 in C++ and would be at offset 8 in Go; remove the packing attribute, or bind Packed by pointer only` |
| register exhaustion | `cppgo: include/mathx/big.hpp:14: mathx::big_call: needs 7 integer argument registers and the ABI has 6; group the arguments into a POD or pass a slice` |
| name collision | `cppgo: include/mathx/a.hpp:6: mathx::scale: maps to Go name Scale, already used by mathx::Vector::scale; rename one of them` |

`-force`, `-no-verify` and any other flag that emits an unvalidated binding do not exist. There is no
path from an uninspectable declaration to a trampoline.

## The error model

Four sources, four shapes, all `errors.Is`/`errors.As`-friendly and wrapped with `%w`:

1. **Loading.** The generated package declares `Open(path string) error`. An empty path uses the
   library named at generation time. `Open` opens the shared object and resolves every symbol it
   needs; it is idempotent. Every binding calls it first: a binding whose Go signature has an error
   result returns the load error, one without an error result panics with it, because there is no
   object and no return channel. Calling `Open` once at startup makes that panic unreachable, which
   is what a program that wants to fail cleanly does.
2. **Construction.** `New<Type>` returns `(*Type, error)`; allocation and load failures arrive here.
3. **The status convention.** A C++ function returning a 32-bit integer can be declared a status
   function with `-status <qualified name>`: `0` means success, non-zero means the library stored a
   message in `cppgo_last_error()`. The Go binding returns `error` instead of the integer and wraps
   the message in `*cppgo.CallError{Symbol, Err}`, which formats as
   `cppgo: mathx::histogram: <message>`. Marking a function whose return type is not a 32-bit
   integer is a generation error.
4. **Use after close.** `cppgo.ErrClosed`, returned by `Close` on a dead object and by a runtime
   `Library` that has been closed.

Typed errors: `*OpenError`, `*SymbolError`, `*NativeError` (the message itself), `*CallError` (which
wraps the native error), and the sentinel `ErrClosed`.

**Exceptions never cross the boundary.** A C++ frame that throws into a generated trampoline has no
handler above it and terminates the process. This is a C++-side obligation: a function bound by
cppgo must not throw. The generator reports a bound function that is not declared `noexcept`, so the
report says which declarations have not made the promise; it does not reject them, because most
usable headers would then be unbindable.

## The ABI it calls

Itanium C++ ABI on SysV AMD64, which is what the host and the generator both measure:

- Integer and pointer arguments: `RDI, RSI, RDX, RCX, R8, R9` in order.
- Float arguments: `XMM0…XMM7` in order; the two files are independent.
- A hidden sret pointer, when there is one, takes the first INTEGER slot; `this` takes the next;
  the explicit arguments follow.
- Result: `RAX` for integer and pointer, `XMM0` for float, up to two registers for a 16-byte POD.
- `this` is the object's address. `const` members are ordinary calls; the `K` in the mangling is
  reported, never assembled by hand.
- Argument registers are not spilled to the stack by the generated trampoline: more than 6 INTEGER
  or 8 SSE slots is a build error. Aggregates never take the MEMORY path (see *POD layout*).
- A slice or string parameter is `(pointer, length)`, pointer first, adjacent in the integer file.
- The callee may not retain a pointer into Go memory after the call returns, and the caller keeps
  the memory alive with `cppgo.KeepAlive`.

## The trampoline

Measured 2026-11-03, Go 1.27, Ryzen 7 6800HS at 964 MHz ("power-saver" profile — the absolute
nanoseconds are inflated by roughly 4.5×, so **cycles and ratios are the honest numbers**):

| path | ns/op | ~cycles |
|---|---|---|
| Go indirect call (baseline) | 2.1 | 2 |
| cgo (Go → C, same function) | 105 | 101 |
| **cppgo trampoline, direct** | **13.9** | **13** |
| cppgo trampoline, stack switch | 14.9 | 14 |

The trampoline is ~7.5× cheaper than cgo and within ~2× of a plain Go call. `make bench`
reproduces it; the README and the site quote it with the clock caveat.

One signature, as generated:

```asm
TEXT ·callNorm(SB), NOSPLIT, $0-24
	MOVQ	fn+0(FP), R12
	MOVQ	this+8(FP), DI
	MOVQ	SP, R13
	ANDQ	$~15, SP        // SysV: RSP 16-aligned *before* the CALL
	CALL	R12
	MOVQ	R13, SP
	MOVSD	X0, ret+16(FP)
	RET
```

Rules that are not negotiable:

- Arguments are read **before** SP is switched and the result is stored **after** it is restored;
  `FP` is relative to SP.
- `NOSPLIT`, zero frame, no allocation, no Go memory touched, no callback into Go.
- `ProbeStack()` runs before the trampoline, from the same goroutine and at or above the foreign
  call. Raising the stack pointer's distance from `stack.lo` is done by entering an assembly
  function with a 32 KiB frame, not a Go frame with a 32 KiB local array (the compiler zeroes it,
  ~1.2 µs measured).

Correctness evidence, all still required on every run: a NOSPLIT asm function is never
asynchronously preempted (`runtime.isAsyncSafePoint` is false for any asm frame and for any
`sp < gp.stack.lo`), GC torture with `GOGC=1` and `runtime.GC()` under 32 goroutines, SIGPROF/SIGURG
torture, `-race`, and `GOMAXPROCS=1`. `//go:linkname runtime.asmcgocall` is rejected by the linker;
do not try it. The documented trade-off stands: a foreign call in flight delays a GC cycle by up to
its duration (2.0 ms call ⇒ 1.1 ms worst cycle), because the P is not released.

## Loading: purego stays

`github.com/ebitengine/purego` is the only third-party runtime dependency, and this is deliberate.
Do not replace it.

Reimplementing `dlopen`/`dlsym` without cgo means `//go:cgo_import_dynamic` directives, per-platform
assembly stubs, and a dynamic loader that breaks quietly when a libc changes symbol versioning. The
decisive reason is not familiarity: a dynamically linked Go binary does not have a libc thread
control block, so any libc code reading thread-local storage — `errno`, `dlerror`, `pthread_getspecific`
— runs against a TCB glibc never initialised. purego solves that in `internal/fakecgo`, which its
non-cgo path imports on purpose. Writing our own loader would mean owning fakecgo too, which is
larger and less forgiving than the loader.

We use only `purego.Dlopen`/`Dlsym` on the hot path; `RegisterLibFunc` is the long-tail fallback for
signatures the hand-written trampoline refuses (by-value aggregates, exotic returns) and for
libclang itself. Our differentiator is not the loader: it is knowing at generation time whether the
binding is possible at all.

## Generation: input, selection, evidence, output

```
cppgo gen -header <path> -package <name> -library <name-or-path> -out <dir>
          [-bind <qualified>]... [-exclude <qualified>]... [-status <qualified>]...
          [-compile-commands <path>]
cppgo check ...        # same run, writes nothing, exits 1 when a file is stale
```

- **`-header`** is the C++ header to bind; it may be repeated. **`-package`** is the Go package name.
  **`-library`** is the shared object: the name `Open("")` loads, and, when it is a readable file,
  the ELF symbol table every binding is checked against.
- **Selection.** With no `-bind`, every public declaration in the headers is a root. Every type that
  appears in a bound signature is generated too (the type closure), even when it is not a root.
  `-bind` adds a root (a class, a struct, a function, or a namespace, which selects what it contains)
  and `-exclude` removes one. They name declarations; they never describe a signature. An unmatched
  `-bind` or `-exclude` is a generation error, so a typo cannot silently shrink the API.
- **Compilation flags** come from `compile_commands.json` and `.clangd`, in clangd's order, never
  invented: `-compile-commands` explicitly, else the nearest database walking up from the header
  (honouring `CompileFlags.CompilationDatabase`), else `.clangd`'s `CompileFlags.Add/Remove/Compiler`.
  The fallback `-std=c++17 -I<header dir>` still exists but the report says it was assumed.
- **Evidence.** libclang is the only source of semantics: it answers types, sizes, offsets,
  visibility, inline-vs-out-of-line, virtual, `noexcept`, defaulted/deleted special members. The ELF
  tier is a **cross-check**, not an inference: `internal/cxx.DefinedDynamicSymbols` reads the
  `.dynsym` of `-library` and the generator fails when a binding's mangled name is not exported by
  the built object. There is no binary-inference tier and no hand-written ABI tier: neither can
  validate, and an unvalidated binding is exactly what this tool does not emit.
- **Output.** `zz_cppgo.gen.go` (types, wrappers, `Open`, symbol table) and `zz_cppgo_amd64.s` (one
  trampoline per bound symbol). Nothing else: the input is C++, and no file is rewritten in place.
  Both files carry the banner, and the Go file carries the exact invocation that produced it, so the
  regeneration command lives in the repository.
- **Determinism.** The same inputs produce byte-identical output regardless of file-system order or
  of how many headers were parsed; bindings are sorted by qualified name. `cppgo check` is the CI
  gate, and the golden files under `internal/gen/testdata` are its unit-level equivalent.
- **Comments.** The C++ doc comment, when there is one, becomes the Go doc comment. Every binding
  then carries exactly one evidence line —
  `// C++: mathx::Vector::norm() const, _ZNK5mathx6Vector4normEv` — and, when the ELF cross-check
  ran, it ends `, verified against libmathx.so`. Nothing else is generated into a comment: the ABI
  register layout belongs in this file, not repeated on every wrapper.

## Not part of this design

Removed, and recorded in [ADR-0001](docs/adr/0001-header-first-bindings.md):

- the Go directive DSL (`//cppgo:library`, `//cppgo:header`, `//cppgo:class`, `//cppgo:ctor`,
  `//cppgo:dtor`, `//cppgo:method`, `//cppgo:function`, `//cppgo:external`, `//cppgo:abi`) and the
  stub file it was rewritten into;
- the `extern "C"` shim mode and its `cppgo_shim.h`;
- the hand-written ABI annotation tier and any flag that emits a binding libclang did not validate;
- `cppgo.Handle` in a generated API.

Non-goals: callbacks from C++ into Go; arm64 and Windows (the package must still build, and the
generator refuses to emit trampolines for an unsupported target); exceptions crossing the boundary;
strings and slices returned from C++.

## Tests and coverage

- `make test` runs two passes, both required:
  `CGO_ENABLED=0 go test -count=1 ./...` (the no-cgo contract) and
  `CGO_ENABLED=1 go test -race -count=1 ./...` (the race detector; the toolchain rejects `-race`
  with cgo off). Coverage is collected on the cgo-enabled pass with `-covermode=atomic`.
- Table-driven tests with `t.Run` per case, `testify` `require`/`assert`, `t.Parallel()` where cases
  are independent. Concurrency tests run under `-race` and `GOMAXPROCS=1` with at least 32
  goroutines.
- Coverage gate: **≥ 99%** on `./...`. The only exclusions are machine-written artefacts:
  `zz_cppgo*.go` and `internal/gen/testdata/`. `cmd/` is measured like everything else, which is why
  `run(args, stdout, stderr) int` carries all the CLI logic and `main` is one statement.
- Every rejection has a test asserting on the complete message, not a substring: the fix is part of
  the contract.
- Every error path has a test: missing library, missing symbol, empty string, closed library, a
  status function whose message is empty.
- The runtime has a test that fails if `internal/cxx` appears in the root package's dependency graph,
  so the two layers cannot quietly merge.
